# STAG-HR

STAG-HR is a PyTorch research toolbox for estimating heart rate from PPG windows. It supports BIDMC and CapnoBase, subject-level intra-dataset evaluation, and explicit cross-dataset evaluation.

## Setup

```bash
bash setup.sh
conda activate tfig
pip install -r requirements.txt
```

Place the datasets under `datasets/` as described in [datasets/README.md](datasets/README.md).

Expected dataset paths:

```text
datasets/
├── bidmc-ppg-and-respiration-dataset-1.0.0/
│   └── bidmc_csv/
└── CapnoBase/
    └── data/csv/
```

## Supported models

| CLI name | Implementation | Description |
|---|---|---|
| `base` | `neural_methods/models/baseline_mlp.py` | MLP baseline |
| `base_trans` | `neural_methods/models/baseline_transformer.py` | Patch-based Transformer baseline |
| `tf_ig` | `neural_methods/models/tf_ig.py` | TF-IG time/frequency dual-branch model |

## Train a model

Training uses the split configuration layout. The selected model is loaded from `configs/models/<model>.yaml`, the dataset from `configs/datasets/<dataset>.yaml`, and shared training values from `configs/common/training.yaml`. The dataset entrypoint selects the model configuration from `--model`.

```bash
python main.py --model base --config configs/train_configs/bidmc.yaml
python main.py --model base_trans --config configs/train_configs/capnobase.yaml
python main.py --model tf_ig --config configs/train_configs/bidmc.yaml
```

The train config files are composition files. They point to `configs/common/training.yaml` and one dataset config; the model-specific file is selected from the model CLI argument.

The model-specific configuration files under `configs/models/`, dataset files under `configs/datasets/`, and shared files under `configs/common/` are the separated configuration reference for new experiments. Existing combined train/infer YAML files remain supported to preserve the current workflow.

## Test a trained model

Use the corresponding inference configuration with `mode: "only_test"` and a checkpoint path:

```bash
python main.py --model base --config configs/infer_configs/base/bidmc.yaml
python main.py --model base_trans --config configs/infer_configs/base_trans/capnobase.yaml
python main.py --model tf_ig --config configs/infer_configs/tf_ig/bidmc.yaml
```

Inference requires:

- an existing `model_path`;
- an existing split manifest generated by the training run;
- the same dataset/window configuration used to create the checkpoint.

Evaluation writes metrics, split metadata, preprocessing metadata, and prediction plots under the model output directory.

## Cross-dataset evaluation

Cross-dataset evaluation is opt-in. The training dataset remains the source of the train/validation subject split, while the declared test dataset is used only for testing.

Example:

```bash
main.py \
  --model tf_ig \
  --config configs/experiments/cross_bidmc_to_capnobase_tf_ig.yaml
```

The cross-dataset configuration declares:

```yaml
evaluation_protocol: cross_dataset
test_dataset_name: capnobase
test_data_path: datasets/CapnoBase/data/csv
```

The test dataset must have a compatible target and signal contract. The input windows are resampled through the existing fixed-length dataset path before reaching the model.

## Configuration layout

```text
configs/
├── common/
│   ├── runtime.yaml
│   └── training.yaml
├── datasets/
│   ├── bidmc.yaml
│   └── capnobase.yaml
├── models/
│   ├── base.yaml
│   ├── base_trans.yaml
│   └── tf_ig.yaml
├── experiments/
│   └── cross_bidmc_to_capnobase_tf_ig.yaml
├── train_configs/
└── infer_configs/
```

Configuration responsibilities:

- `common/`: shared training and runtime defaults.
- `datasets/`: dataset path and window defaults.
- `models/`: architecture-specific parameters.
- `experiments/`: explicit evaluation protocol examples.
- `train_configs/` and `infer_configs/`: backward-compatible executable configurations.

## Outputs

Training and testing artifacts are written under:

```text
pretrained_models/
└── <model>_<dataset>/
    ├── best_model.pth
    ├── eval_predictions_test.png
    ├── logs/
    └── reports/
        ├── history.json
        ├── preprocessing_config.json
        ├── split_info.json
        └── test_report.json
```

Raw datasets and generated checkpoints should not be committed.

## Model profiling

Use `utils/summary.py` to benchmark a model:

```bash
python utils/summary.py --model tf_ig --device cpu
python utils/summary.py --model base_trans --sequence-length 1875 --device cpu
```
